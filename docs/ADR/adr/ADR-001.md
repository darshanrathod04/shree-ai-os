During the Platform Blueprint review, an inconsistency was identified between:

ADD-201 — Platform Architecture
STD-003 — Platform Core Engineering Standard

ADD-201 clearly separates:

Layer 4
Platform Core

from

Layer 5
Platform Kernels.

However, STD-003 listed both Platform Core Services and Platform Kernels under the same engineering scope.

This violates the Platform's architectural layering.

Decision

STD-003 SHALL apply only to Platform Core Services.

Platform Kernels SHALL continue to follow STD-002 — Kernel Development Standard.

Updated Scope of STD-003

The following components are governed by STD-003:

Platform Core

├── Kernel Registry
├── Discovery Service
├── Lifecycle Manager
├── Event Bus
├── Configuration Service
├── Health Monitor
├── Kernel Loader (Future)
├── Scheduler (Future)
├── Policy Engine (Future)
├── Resource Manager (Future)
├── Security Manager (Future)
└── Distributed Coordinator (Future)
Removed from STD-003 Scope

The following are Platform Kernels and therefore governed by STD-002:

Runtime Kernel
Identity Kernel
Memory Kernel
Knowledge Kernel
Planning Kernel
Reasoning Kernel
Capability Kernel
Plugin Kernel
Security Kernel
Analytics Kernel
Audit Kernel
Vision Kernel
Learning Kernel
Future Kernels
Architectural Rationale

Platform Core and Platform Kernels have fundamentally different responsibilities.

Platform Core

Provides infrastructure.
Coordinates execution.
Does not implement intelligence.

Platform Kernels

Provide reusable intelligent capabilities.
Own domain behavior.
Evolve independently.

Combining them under one engineering standard would blur architectural boundaries and reduce long-term maintainability.

Consequences
Positive
Perfect alignment with ADD-201.
Clear ownership boundaries.
Independent evolution of Platform Core and Kernels.
Easier onboarding for future engineers.
Simpler review process.
Better scalability over the next decade.
Negative
STD-003 requires a minor update to its "Applies To" section.

No implementation changes are required.

Architectural Principle Reinforced

Infrastructure and Capability shall evolve independently while collaborating through stable platform contracts.
